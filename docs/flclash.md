# FlClash：开着代理访问校园网站

[返回首页](../README.md)

核对版本：**FlClash v0.9.2**。以下菜单名称与生效条件按官方源码核对；设置后按最后一节检查实际连接。

目标是保留代理服务，让 `bjut.edu.cn` 及其子域名通过本地网络直连。对于校园内网资源，设备仍需处于可访问该资源的校园网环境，或已接入学校提供的远程访问服务。直连规则不能代替校园网接入权限。

## 1. 选择规则模式

在“仪表盘”的“出站模式”中选择“规则”。保持已能正常工作的系统代理或虚拟网卡设置，启动 FlClash。这里的“规则”决定连接怎样分流；下一步的“标准”决定怎样扩展订阅，两处都要检查。

## 2. 确认当前订阅使用标准扩展

先检查已有扩展：**正在使用脚本扩展或自定义配置的用户，保留现有方式，将校园规则合并到原脚本或配置；不要直接切换，以免停用已有分流。** 可参考[通用规则](common-rules.md)。

普通订阅用户进入“配置”，打开当前订阅的“⋯”菜单，选择“扩展”，确认“扩展模式”为“标准”，再继续下文。如果本来已有标准扩展设置，保留原有条目。如出现“立即应用”，点击它；返回时也会检查并应用修改。

本文的全局附加规则只供使用标准扩展的 URL、文件配置加载；脚本扩展和自定义配置不使用这一列表。[官方扩展页面实现](https://github.com/chen08209/FlClash/blob/v0.9.2/lib/views/profiles/extend/extend.dart)

## 3. 添加校园直连规则

打开 **工具 → 进阶配置 → 附加规则**，点击“＋”，填写：

| 字段 | 填写内容 |
|---|---|
| 代理类型 | `DOMAIN-SUFFIX` |
| 内容 | `bjut.edu.cn` |
| 分流策略 | `DIRECT` |

点击“保存”。“内容”栏只填域名，不加 `https://`、`*.`、分号或页面路径。这条规则会匹配学校主域名和子域名；不覆盖学校使用的其他独立域名。[菜单入口](https://github.com/chen08209/FlClash/blob/v0.9.2/lib/views/config/advanced.dart)、[规则表单](https://github.com/chen08209/FlClash/blob/v0.9.2/lib/features/form/rule.dart)

回到当前订阅的“扩展 → 标准”，进入“控制全局附加规则”，确认新规则开关开启。若同一网站仍被其他规则提前匹配，检查当前订阅自己的附加规则：它们排在全局附加规则前面。全局附加规则保存于本地数据库，普通订阅更新不会将其替换；删除应用数据则会丢失。新增订阅也要确认使用标准扩展，且没有禁用这条规则。[规则存储、筛选与顺序](https://github.com/chen08209/FlClash/blob/v0.9.2/lib/database/rules.dart)

## 4. 重新发起请求并验证

保存后重新打开校园页面，必要时关闭该网站已有连接再访问。到“连接”或“最近请求”中查找对应域名，确认命中校园规则，出口为 `DIRECT`；再访问一个原本需要代理的网站，确认仍走代理节点。附加规则变化会触发正在使用标准扩展的配置重新应用；若页面提示有未应用修改，先点击“立即应用”。

页面返回 `200` 只说明收到了成功状态的 HTTP 响应，不能单独证明直连或登录成功。若主页面成功、登录或资源加载失败，检查跳转域名和接口请求，按实际主机名补规则。采用内核的 `DIRECT` 分流时，连接仍进入 FlClash 再直连，因此通常能在连接记录中看到它；这与桌面端“排除域名”让应用绕过系统代理的机制不同。
