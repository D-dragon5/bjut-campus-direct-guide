# 规则加了，仍打不开怎么办？

[返回首页](../README.md)

先选择有权访问的目标，分别检查“网络能否到达”“域名能否解析”“请求走哪条路”“账号是否有权限”。每次改一项，再重新建立连接比较。

| 现象 | 下一步 |
|---|---|
| 关闭 Clash 的系统代理和 TUN 后也打不开 | 先确认校园网络接入或学校 WebVPN 入口；仅关闭应用界面不一定关闭后台接管 |
| 校外直接打开 `my.bjut.edu.cn` 不通 | 按[学校公开说明](https://undergrad.bjut.edu.cn/info/1213/3603.htm)访问 `webvpn.bjut.edu.cn`，从其中进入资源 |
| 登录页可打开，登录后页面或附件失败 | 查看浏览器地址栏、开发者工具 Network（网络）或客户端连接页的实际请求主机；跳转到其他域名时，仅补充确认需要直连的域名 |
| 已加系统代理绕过，但连接页仍看到校园代理流量 | 检查 TUN、浏览器代理插件、应用独立代理，以及系统代理是否为 PAC 模式；改用规则分流并检查最终出口 |
| 已添加校园规则，但出口仍为代理节点 | 确认规则模式、规则位置、当前订阅、最终配置及新连接；FlClash 还要检查是否启用了会加载附加规则的标准扩展 |
| 校园域名解析不到，或得到与校内预期不同的地址 | 检查当前网络的 DNS 设置、浏览器安全 DNS 和 TUN DNS 接管；向学校核对官方解析要求，不随意硬编码网上找到的 DNS 或业务 IP |
| 已显示 `DIRECT`，但校园 VPN 与 TUN 同开仍失败 | 检查学校 VPN 的路由和 DNS 是否被另一套接管影响；可先关闭 TUN，仅用系统代理验证。已知网段的 TUN 排除按客户端/学校文档单独配置 |
| 网页返回 `200`，仍不能查看资源 | 检查登录是否完成、页面是否是认证/提示页、账号是否具有该资源权限 |
| 打开数据库网页却没有学校访问权限 | 按图书馆规定采用校园网、WebVPN 或资源支持的 CARSI 认证；访问网页不等于获得机构授权 |
| 更新或切换订阅后失效 | 检查自定义项保存位置；使用客户端持久化入口，且核对当前订阅是否加载它 |

DNS 是域名系统（Domain Name System）。`DIRECT` 规则不自动保证域名由校内 DNS 解析。可参考 [Mihomo DNS 配置文档](https://wiki.metacubex.one/config/dns/)，但应先保留原配置，确认具体问题后再调整。

TUN 是通过虚拟网络接口接管请求的一种方式；它和“全局出站模式”是独立设置。TUN 接管后仍可按规则直连。详见[官方绕过方式区分](https://www.clashverge.dev/guide/bypass.html)及 [TUN 配置](https://wiki.metacubex.one/config/inbound/tun/)。

## 如何恢复到修改前？

- 在系统代理绕过中，仅删除新增的校园条目，或还原事先保存的文本。
- 在前置/附加规则中，仅删除或关闭本次新增项，再应用配置。
- 恢复本次修改过的开关；关闭旧网页/应用连接后重试。

## 反馈时提供什么？

说明客户端名称和版本、Windows/macOS/Linux/Android、系统代理或 TUN、出站模式，以及失败的主机名和错误提示即可。截图前遮住学工号、姓名、订阅 URL、认证参数、令牌和个人设备地址。不要公开完整订阅、业务系统登录过程或未脱敏的连接日志。
